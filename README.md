# 岩芯薄片显微照片索引台 —— 可续作操作账

纯静态页面（`index.html` + `app.js` + `journal.js`），无构建步骤。
打开 `index.html` 即可使用；`npm test` 运行核心逻辑测试（Node 内置 test runner）。

## 解决的问题

旧版把样本、照片、批注直接覆盖写进一个 localStorage 对象：

- 两个标签页同时提交，后写的整份状态盖掉先写的；
- 写入中断会留下半截 JSON；
- 没有操作编号，无法判断两次修改是顺序还是并发。

## 存储模型

localStorage 两个键：

| 键 | 内容 |
| --- | --- |
| `wxyy-2-thin-section-index` | 主文档：`{version, seq, log[], checkpoint}` |
| `…__backup` | 每次提交前先写的同内容备份 |

- **操作账 `log`**：每次录入/编辑/删除/勾选对比/冲突裁决都是一条操作，
  `{id, seq, clientId, ts, type, baseSeq, …}`，编号在跨标签页锁
  （Web Locks API）内提交时连续分配。
- **检查点 `checkpoint`**：操作数达到阈值（默认 50）后把旧账物化折叠，
  只保留各字段的存活版本链；之后从检查点继续重放新账。
- **待办队列 `pending`**（仅内存）：操作先生成（固定 id/载荷/baseSeq）并入队、
  乐观显示，再落账。写入失败队列不动，重试沿用首次那条操作，天然幂等。

## 合并与冲突

每个样本字段各自维护版本链，合并时以 `baseSeq` 判定关系：

- 两个标签页改**不同字段** → 双方字段都保留，无冲突；
- 改**同一字段且值相同** → 自动收敛；
- 改**同一字段且值不同、互相没见过对方编号** → 两个版本都保留，
  页面顶部"待确认版本"面板里各列一版，可选其一或填写最终值，
  裁决本身也是一条带编号的 `resolve` 操作；
- **删除与编辑并发** → 样本进入删除冲突（删除 / 保留两个去留版本），
  先定去留，保留后并发的字段版本再按字段冲突处理；
- 同一标签页内的连续编辑是因果顺序，只覆盖不冲突。

## 派生快照失效

对比视图和导出清单都是从当前视图按操作编号生成的快照
（`sourceSeq`）。样本信息一变，编号前进：

- 旧快照立即标记为失效（对比栏显示失效提示）；
- 下次勾选对比 / 点击导出时按新编号现场重算，缓存命中时不重算。

## 写失败与恢复

- 写入顺序：先写备份键 → 再写主键 → 读回比对，不一致即判失败；
- 失败后内存中的待办操作保留，状态条显示"重试"，切回标签页也会自动续作；
- 重新打开时依次尝试：主文档 → 备份 → 抢救检查点 → 空账，
  并在状态条说明恢复来源；操作始终从最后完整编号续接。

## 旧记录

首次打开旧版 `{samples, compare}` 数据时自动迁移：

- 每条旧样本（含照片 dataURL、批注）转成一条带编号的 `create` 操作，
- 旧的对比勾选转成一条 `compare` 操作；
- 迁移后写为 v2 新账，照片、批注、样本继续可用，且只迁移一次。

## 文件

- `journal.js` — UMD 纯逻辑核心（物化/合并/快照/恢复/迁移），可在 Node 直接测；
- `app.js` — 浏览器层（DOM、Web Locks、storage 事件、重试与冲突 UI）；
- `test/journal.test.js` — 核心场景测试（合并、冲突、删除、快照、恢复、迁移）；
- `test/browser.smoke.test.js` — 浏览器层整链路冒烟。
